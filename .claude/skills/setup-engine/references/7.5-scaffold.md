## 7.5 Scaffold the Engine Project

**Without this step the framework produces source files no engine can open.**
`/dev-story` writes `.cs` files under the code root (`Assets/`), and the `minimal` path
advertises "four steps to running code" — but no skill writes a Unity project for
the editor to load.

### Unity — instruct, do not fabricate

A Unity project is editor-generated and spans many files, several of them binary
or machine-specific. This repo cannot source their correct contents, and a
hand-written scaffold would be the exact failure Section 7's sourcing rule
forbids — something that looks finished and is quietly wrong.

**If `ProjectSettings/ProjectVersion.txt` already exists at the repo root**, the
project exists: say so and skip to Section 8 — its settings are the developer's.

Otherwise tell the user, in one short block, that CCGS does not create the Unity
project and they should create it first: create the project in Unity Hub **at the
repo root** (so `Assets/`, `Packages/` and `ProjectSettings/` sit next to
`.claude/`), choosing the URP template matching the 2D/3D answer from Section 2,
then re-run `/setup-engine`.

Report the outcome in the Section 12 summary either way — already present, or
"not created, engine requires the editor" — so the user leaves this skill knowing
whether a runnable project exists.

> **Deliberately not a `project.yaml` key.** An `engine.project_scaffolded` flag
> would be written here and read by nothing, which is a dead setting — the same
> writer-without-reader defect the config gates exist to catch. The filesystem is
> the source of truth: any skill that needs to know globs for
> `ProjectSettings/ProjectVersion.txt`.
